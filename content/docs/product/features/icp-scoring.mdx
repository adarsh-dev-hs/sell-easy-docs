The **ICP & Scoring** screen (`/scoring`) controls how every account is scored. You describe your ideal customer (industries, countries, size, revenue, technologies, funding), set how much **fit** counts against **intent**, choose how much each signal type matters and how fast intent fades, and set the tier cut-offs. A **live preview** re-scores all accounts with your draft before anything is saved.

**Who uses it:** RevOps (admins can save). Anyone can use the preview to explore what-if scenarios.

## Page layout

| Card | Contents |
|---|---|
| **Firmographic fit** | Industries, countries, min/max employees, min revenue ($M), technologies, funding stages |
| **Weights** | Fit vs intent slider, intent half-life, one weight slider per signal type |
| **Tier thresholds** | Minimum score for A, B and C, with sliders, number inputs and a colour bar showing the D/C/B/A bands |
| **How scoring works** | The formulas, filled in with your current draft values |
| **Live preview** | Tier changes, promoted/demoted counts, average score and delta, Current vs Draft tier chart |
| **Top 10 accounts** | Ranked by draft score, with delta and the previous tier when it changed |

The header shows **Unsaved changes** when the draft differs from the saved configuration, plus the time it was last saved. The actions are **Reset to defaults**, **Discard** and **Save & re-score** (admins only).

## How the score is calculated

```text
fit    = industry(25) + size(20, or 8 if within 50%–150% of range) + geography(15)
         + revenue(15) + tech(5 per match, max 15) + funding(10)            → 0–100

intent = min(100, Σ strength × weight(type)/100 × 0.5^(age / halfLife) × 0.45)
         (signals older than 3 × halfLife are ignored)                      → 0–100

score  = round( fit × fitWeight/100 + intent × (1 − fitWeight/100) )
tier   = A ≥ A-threshold > B ≥ B-threshold > C ≥ C-threshold > D
```

[Core concepts](/docs/product/core-concepts#worked-example-default-icp) walks through a full example.

## Validation rules

The page checks the draft as you edit, and the API checks it again on save. Errors appear in a red alert and disable **Save**.

| Rule | Checked by |
|---|---|
| At least one industry | UI + API |
| Min employees ≤ max employees | UI + API |
| Employee counts and minimum revenue ≥ 0 | UI + API |
| Tier thresholds strictly descending: A > B > C | UI + API |
| Tier C threshold > 0 | UI only (the API accepts 0) |
| Half-life ≥ 1 day | UI + API (the API also caps it at 365) |
| Each weight and threshold between 0 and 100 | UI (sliders and clamped inputs) + API |

If the server rejects a configuration, its field errors are listed under "The server rejected this configuration".

## Live preview

<Steps>
<Step>Edit any setting. After a **400 ms** pause, the draft is sent to `POST /icp/preview`. Drafts that fail validation aren't sent, and the last valid result stays on screen with a spinner while the new one loads.</Step>
<Step>

The API scores every **non-duplicate** account twice, once with the **saved** ICP and once with the **draft**, using all signals as of now. It returns:

- **tier changes**: accounts whose tier would change, split into **↑ promoted** (for example C → B) and **↓ demoted**;
- **avg score**: the draft average and its change from the current average;
- **distribution**: account counts per tier, current vs draft;
- **top 10**: accounts with the highest draft scores, with delta and previous tier.

</Step>
<Step>Nothing is saved. Viewers and members can use the preview as a what-if tool, and the page says "Only workspace admins can save changes".</Step>
</Steps>

## Saving

<Steps>
<Step>Click **Save & re-score** (admins only). The whole configuration is replaced.</Step>
<Step>The API re-scores **every** account (duplicates included). Each gets a score history point with reason **"ICP configuration updated"**.</Step>
<Step>A message reports *"ICP saved — N accounts changed score or tier"*. The page reloads the saved configuration.</Step>
</Steps>

<Callout type="info">
The bulk re-score on save does **not** log a `score_change` activity for each account. Only individual re-scores do. The history point is always recorded.
</Callout>

**Reset to defaults** loads the default ICP into the **draft** after you confirm. You still need to save. **Discard** returns the draft to the saved configuration.

## Effects elsewhere

- **Playbooks** match on the tier and score calculated at the moment a signal is processed. After you change thresholds, new signals follow the new tiers right away.
- The **account page** breakdown and intent contributors always use the saved ICP.
- **Analytics → Tier performance** groups accounts by their stored tier, so it reflects the most recent re-score.

## Edge cases & limitations

- There is one ICP per workspace. Segment-specific ICPs aren't supported.
- The pick lists for industries, countries, technologies and funding stages are fixed product constants. Accounts with other values (for example from an import) never match those criteria.
- Intent is only recalculated when an account is re-scored, so stored intent doesn't fade by itself between signals. Save the ICP or use **Re-score** to refresh it.
- The preview's *current* column is recalculated now. It can differ from the stored score if intent has decayed since the account was last scored.
- The ICP has no version history. Only `updatedAt` is kept.
