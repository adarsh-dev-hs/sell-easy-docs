Cloud cost for the three months from **5 October to 31 December 2026**, based on the [target architecture](/docs/architecture/target-architecture) and the topology in [Engineering → Deployment](/docs/engineering/deployment).

<Callout type="warn" title="Basis of these estimates">
**AWS us-east-1, on-demand list prices, no Savings Plans, no credits, excluding tax and support plans.** Converted at an assumed **₹88 per USD**. Sized for pilot scale: up to about 10 workspaces, 50 users, ~20k signals and ~10k emails per month, a few GB of data. Prices change — check the AWS Pricing Calculator before you commit. Every figure here is an **estimate**.
</Callout>

## Two ways to run this

<Cards>
  <Card title="Lean — one environment" description="App Runner + a small RDS instance. No ALB, no NAT Gateway, no staging tier. About ₹7,700 per month. Right if cash is tight and the team can deploy carefully." />
  <Card title="Safer — three environments" description="ECS Fargate behind an ALB, dev / staging / production separated. About ₹33,400 per month. Right if a pilot customer's data is in production." />
</Cards>

The budget uses a **ramp between the two**: lean in October, safer by December when a pilot customer is on it.

## Lean option — one environment, service by service

Uses **App Runner** instead of ECS + ALB + NAT. App Runner terminates TLS, scales and gives you a URL with no load balancer and no NAT Gateway to pay for. It is less configurable and harder to lock into a private VPC, which is exactly the trade.

| Service | Sizing assumption | USD / month | **₹ / month** |
|---|---|--:|--:|
| **App Runner** | 1 service, 0.5 vCPU / 1 GB, always on | $28 | **₹2,464** |
| **RDS PostgreSQL** | `db.t4g.small`, single-AZ, 20 GB gp3, 7-day backups | $27 | **₹2,376** |
| **S3 + CloudFront** | Frontend static assets | $8 | **₹704** |
| **Secrets Manager + KMS** | ~10 secrets | $5 | **₹440** |
| **CloudWatch** | Logs and a handful of alarms | $10 | **₹880** |
| **SES** | Low volume | $2 | **₹176** |
| **Route 53, ECR, data transfer** | | $8 | **₹704** |
| **Lean total** | | **$88** | **≈ ₹7,744** |

<Callout type="info" title="What the lean option gives up">
No staging environment (you test in production, or locally), no private-subnet isolation, no ALB-level WAF, no Multi-AZ. Acceptable while the only data is yours. **Not acceptable once a pilot customer's contact data is in the database** — at that point move to the safer option, which is why the ramp below crosses over in November.
</Callout>

Safer option, monthly, at pilot scale.

| Environment | What runs there | USD / month | **₹ / month** |
|---|---|--:|--:|
| **Production** | Full stack as above | $245 | **₹21,560** |
| **Staging** | Same services at the smallest sizes, single-AZ, no NAT, scaled down overnight | $90 | **₹7,920** |

**Stakeholder demo:** effectively free. Mock data mode runs the backend logic in the browser, so a public demo needs only a frontend deployment — no database, no secrets, no backend. See [Environments & data modes](/docs/architecture/environments-and-data-modes).

### Frontend hosting: Vercel or CloudFront + S3

| Option | USD / month | **₹ / month** | Pros | Cons |
|---|--:|--:|---|---|
| **Vercel Pro** | $20 per member + usage; 2 members ≈ $40–$60 | **₹3,520 – ₹5,280** | Preview deploys on every PR, zero ops, already used for the demo | A second vendor and a second bill; commercial use is **not** permitted on the free Hobby plan |
| **CloudFront + S3** | $8 – $20 | **₹704 – ₹1,760** | One cloud, one bill, WAF in front of web and API | Needs a static-export-compatible build and CI work — engineer time that is scarcer than ₹3,000 a month |

**Recommendation for these three months:** pay for Vercel. The preview deployments are worth more than the ₹3,000 monthly difference to a three-person team, and the CI work to move to S3 is engineer-weeks you do not have.

Expected case. Environments come online as the roadmap needs them.

| Month | What is running | USD | **₹** |
|---|---|--:|--:|
| **M1 · Oct 2026** | Dev from week 1; staging from week 3; Vercel previews. No production. | $120 | **₹10,500** |
| **M2 · Nov 2026** | + production from mid-month (pilot data arrives), NAT, ALB, Secrets Manager | $280 | **₹24,500** |

| **Expected total** | | **$795** | **₹70,000** |
| **Low** | Lean path throughout, no separate staging | $341 | **₹30,000** |

<Callout type="success" title="Free tier and credits can take this close to zero">
This estimate deliberately assumes **no credits**, so the number is defensible. In practice:

- **AWS Free Tier** (new accounts, 12 months) covers 750 hours a month of `db.t4g.micro` RDS, 5 GB of S3, 1 TB of CloudFront egress and a generous CloudWatch allowance — enough to run the dev and staging tiers at near-zero cost.
- **AWS Activate** gives startups credits from **$1,000** (Founders, self-serve) up to **$5,000–$100,000** through an accelerator, incubator or VC referral. **$1,000 ≈ ₹88,000** — more than the entire expected infrastructure budget for this quarter.
- **Anthropic, GitHub and Vercel** run similar startup programmes worth checking.

Apply for AWS Activate in **week 1**, not week 10. If credits land, treat the ₹70,000 as recovered contingency rather than as budget to spend.
</Callout>

## Cost levers, cheapest first

| Lever | Saving | Trade-off |
|---|---|---|
| **Apply for AWS Activate credits** | Up to the entire line | Application takes days, not hours — start in week 1 |
| **Drop the NAT Gateway** — VPC endpoints for S3, SQS and Secrets Manager, or run tasks in public subnets with tight security groups | ~$38/mo (**₹3,300**) | Endpoints have their own hourly cost; public subnets need careful security groups |
| **Scale staging to zero overnight and at weekends** | 50–65% of staging (**~₹4,500/mo**) | A scheduled scaling rule the SSE has to write and maintain |
| **Single-AZ RDS during the build** (already assumed) | ~50% of the RDS line | No automatic failover. Acceptable pre-launch, revisit before real customer data |
| **Graviton instance classes** (`t4g`, already assumed) | ~20% vs. `t3` | None worth mentioning |
| **CloudWatch log retention at 14 days**, archive to S3 | ₹500 – ₹1,000/mo | Shorter forensic window |
| **Do not provision Redis or OpenSearch** (already assumed) | ~$65/mo (**₹5,700**) | Only valid while Postgres meets latency targets — measure first, per the [migration principles](/docs/architecture/target-architecture#principles-for-the-migration) |
| **AWS Budgets and cost-anomaly alerts from day one** | Prevents surprises | Fifteen minutes of setup; do it in week 1 |

**Not worth doing in a three-month window:** Savings Plans or Reserved Instances. They need a one- or three-year commitment against a workload whose shape you will not know until January.
