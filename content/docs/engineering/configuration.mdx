The API reads its configuration from environment variables, loaded from `backend/.env` by `dotenv` (`import "dotenv/config"` in `src/config.ts`). `backend/.env.example` lists every key the target architecture needs. **Only a subset is validated and used today**; the rest are reserved for drivers and adapters that aren't built yet. The web app needs two variables: where its data comes from, and the API URL.

## How configuration is loaded

```ts title="backend/src/config.ts (excerpt)"
const parsed = schema.safeParse(process.env)
if (!parsed.success) {
  console.error("❌ Invalid environment configuration:")
  for (const issue of parsed.error.issues) console.error(`  - ${issue.path.join(".")}: ${issue.message}`)
  console.error("Copy .env.example to .env and fill in the values.")
  process.exit(1)
}

export const config = {
  ...env,
  isProd, // NODE_ENV === "production"
  isTest: env.NODE_ENV === "test",
  corsOrigins: env.CORS_ORIGINS.split(",").map((s) => s.trim()).filter(Boolean),
  dataDir: path.resolve(process.cwd(), env.DATA_DIR),
  enableSimulation: env.ENABLE_SIMULATION,
  enableAdminReset: env.ENABLE_ADMIN_RESET && !isProd,
}
```

- Validation happens **once, at import**. Any invalid value stops the process with a readable list of errors.
- Variables that aren't in the schema are ignored by `config`. Nothing reads `process.env` elsewhere, except test setup.
- Booleans (`ENABLE_*`) accept `true`, `false`, `1` or `0`, and **default to `false`** when unset. Note that `.env.example` sets both to `true`.
- `DATA_DIR` is resolved relative to the **current working directory**. `npm` scripts run in `backend/`, so `./db` means `backend/db`.
- Real environment variables take precedence over `.env`, because `dotenv` doesn't override variables that are already set.

**Legend.** *Validated* means the key is in the zod schema in `config.ts`. **Active** means code reads it today. **Reserved** means it is documented for a future driver or adapter and nothing reads it.

## Core

Only this block needs values to run the app today.

| Variable | Example / default | Required | Validated | Status | Used by |
|---|---|---|---|---|---|
| `NODE_ENV` | `development` | no | `development \| test \| production` | **Active** | Prod mode: disables admin reset, 20 attempts per 15 min on auth endpoints, JSON logs, Slack notifications. `test` silences logs and removes mock delays. |

## Frontend

`frontend/.env.local`, copied from `frontend/.env.example` by `npm run setup`:

```bash title="frontend/.env.example"
# Where the app gets its data:
#   api  — call the SellEasy backend at NEXT_PUBLIC_API_URL (default)
#   mock — run fully in the browser with demo data (no backend needed; e.g. a Vercel demo)
NEXT_PUBLIC_DATA_SOURCE=api

# URL of the SellEasy API (backend/) — used when NEXT_PUBLIC_DATA_SOURCE=api
NEXT_PUBLIC_API_URL=http://localhost:4000/api/v1
```

| Variable | Default | Values | Used by |
|---|---|---|---|
| `NEXT_PUBLIC_DATA_SOURCE` | `api` | `api \| mock`. Any value other than `mock` means `api`. | `frontend/src/lib/api/client.ts` (`DATA_SOURCE`, `IS_MOCK`). `mock` routes every request to the in-browser API in `src/mock-api` and shows the demo-mode hints on the login page and header. See [Mock data mode](/docs/engineering/frontend/mock-mode). |
| `NEXT_PUBLIC_API_URL` | `http://localhost:4000/api/v1` | URL | `frontend/src/lib/api/client.ts` (`API_URL`, trailing slash removed). The fallback is the same URL. Ignored in `mock` mode. |

<Callout type="warn" title="NEXT_PUBLIC_* values are inlined at build time">
Next.js replaces `process.env.NEXT_PUBLIC_*` with literal values when it builds (and when `next dev` starts). Changing either variable needs a restart of `next dev`, or a **new build and redeploy** (on Vercel, redeploy after editing the environment variable). A running deployment never switches data source on its own.
</Callout>

In `api` mode, the origin the web app is served from (for example `http://localhost:3000`, or your Vercel domain) must be listed in the backend's `CORS_ORIGINS`. Mock mode makes no network calls to the API, so CORS doesn't apply. The root script `npm run dev:mock` sets `NEXT_PUBLIC_DATA_SOURCE=mock` with `cross-env`.

## Generating secrets

```bash
openssl rand -hex 32   # JWT_SECRET (any long random string works)
openssl rand -hex 32   # ENCRYPTION_KEY (must be exactly 64 hex chars)
# or, without openssl:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`npm run setup` does this automatically the first time it creates `backend/.env`.

<Callout type="warn" title="Treat ENCRYPTION_KEY as non-rotatable data">
Stored vendor credentials can only be decrypted with the key that encrypted them. Keep a copy in your secrets manager. Changing the key forces every integration to be reconnected.
</Callout>

| Variable | Local development | Test (vitest) | Staging | Production |
