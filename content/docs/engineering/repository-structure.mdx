SellEasy lives in one working directory with three apps side by side. Each app has its own `package.json`, `node_modules` and lockfile. The root holds only shared tooling. This page explains what each important folder and file is for.

| Path | Purpose |
|---|---|
| `src/server.ts` | Entry point. Warns if no organization exists, starts listening on `PORT`, and shuts down cleanly on SIGINT and SIGTERM. |
| `src/app.ts` | `createApp()`. Sets up the middleware stack (pino-http, helmet, cors, compression, JSON body limit), `/health`, the rate-limited `/api/v1` router, all 18 modules, `openapi.json` and the Swagger UI, then the 404 and error handlers. |
| `src/config.ts` | Loads the environment with zod. The process exits with a readable list of problems if a value is invalid. Also derives `corsOrigins`, `dataDir`, `enableSimulation` and `enableAdminReset`. |
| `src/lib/route-runtime.ts` | The transport-agnostic route runtime (no Node or Express imports). `RouteDef` and `RouteContext`, `executeRoute()` (auth mode, role checks, zod parsing, the `{ data }` envelope, status codes), `errorOutput()`, `paged()`, `fileResponse()`, `routeRegistry`, and the shared schemas `listQuery`, `csvList`, `boolQuery`, `idParams`, `idList` plus the `parseSort` helper. |
| `src/lib/http.ts` | `createModule(tag, basePath)` and `route({...})`. Registers each definition in `routeRegistry` (for OpenAPI) and binds it to an Express router. Re-exports everything from `route-runtime.ts`. |
| `src/lib/roles.ts` | `AuthContext`, `atLeast(role)` and `assertRole()` |
| `src/lib/openapi.ts` | Builds the OpenAPI 3.1 document from the route registry |
| `src/lib/errors.ts` | `HttpError` and its helpers: `badRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`, `unprocessable`, `must` |
| `src/lib/expand.ts` | `withAccounts` and `withContacts`, which attach `account` and `contact` summaries to list items |
| `src/lib/crypto.ts` | AES-256-GCM `encrypt` and `decrypt`, `sha256`, `mask`, `randomSecret` (built on `randomToken`) |
| `src/lib/ids.ts` | `newId(prefix)`, `randomToken`, `randomHex`, `nowIso`, `DAY_MS`. Uses the Web Crypto RNG, so it runs in Node and browsers. |
| `src/middleware/auth.ts` | `signToken`, `authenticateBearer`, `authenticateApiKey` and `authenticateRequest` (JWT and API-key authentication). Re-exports `assertRole` and `atLeast`. |
| `src/middleware/error.ts` | The error envelope. Maps body-parser failures to `invalid_json` and `payload_too_large`. |
| `src/db/repository.ts` | The storage-agnostic `Repository<T>` interface and the `Where<T>` query language |
| `src/db/memory/memory-repository.ts` | `MemoryRepository`: the portable in-memory collection with all query logic, the per-collection write queue and `loadRows()`/`persistRows()` hooks. Also exports `matches` and `sortRecords`. |
| `src/db/json/json-repository.ts` | The JSON-file driver: `extends MemoryRepository` and adds file loading and atomic temp-file-then-rename writes |
| `src/db/postgres/` | Placeholder for the Postgres driver (it throws if selected) and an empty `migrations/` folder |
| `src/db/index.ts` | `db`, the registry of all 19 collections, with the file name and ID prefix for each |
| `src/domain/types.ts` | **Source of truth** for the domain types |
| `src/domain/constants.ts` | Business constants: industries, stages, deal probabilities, the integration catalog, the default ICP and API scopes. `GET /meta` serves them. |
| `src/events/bus.ts` | The in-memory `EventBus` (portable, no `node:events`), with domain events such as `signal.ingested` and `deal.stage_changed` |
| `src/providers/index.ts` | Vendor adapter interfaces and their **mock** implementations |
| `src/modules/<service>/routes.ts` | The HTTP contract for a service |
| `src/modules/<service>/service.ts` | The business logic for a service. Some modules have extra files, for example `scoring/engine.ts` and `outreach/enrollment.ts`. |
| `src/seed/` | The demo dataset generator and `clearOrgData` and `seedDemoData` |
| `scripts/` | `bootstrap.ts`, `seed-demo.ts` and `reset.ts`, run with `tsx` |
| `tests/api.test.ts` | End-to-end API tests using supertest against `createApp()`, with an isolated temp `DATA_DIR` |
| `db/` | The JSON database, one `<collection>.json` array per collection. Everything except `.gitkeep` is git-ignored. |
| `dist/` | Output of `npm run build` (git-ignored) |

The module folders map to API tags like this: `organization` holds both the **Organization** routes (`/org`, `/me`, `/users`, `/api-keys`) and the auth service that `auth/routes.ts` uses. `signals/routes.ts` exports two modules, **Signals** and **Webhooks**. `outreach` serves `/sequences`, `/enrollments`, `/mailboxes`, `/inbox` and `/outreach/stats`. `pipeline` serves `/deals`.

| `src/lib/types.ts` | API contract types, mirrored from `backend/src/domain/types.ts` |

| `src/lib/format.ts` | Formatting helpers: `currency`, `percent`, `timeAgo`, `shortDate`, `initials` |

| `src/mock-api/core/` | **Generated.** A copy of `backend/src` with browser overrides applied. Never edit it by hand; run `npm run mock:sync`. Committed so the frontend builds without the backend folder. |

| `src/mock-api/shims/` | A no-op `express-rate-limit` for the browser |
| `scripts/sync-mock-core.mjs` | Generates `src/mock-api/core` (`npm run mock:sync`) or checks that it's current (`npm run mock:check`) |

## Git repositories

<Callout type="warn" title="There are several git repositories here, not one">
The `sell-easy/` root is **not** a git repository. Each app has its own `.git` directory:

- **`backend/`** is its own repository with remote `git@github.com:adarsh-dev-hs/sell-easy-backend.git`, on branch `main`.
- **`frontend/`** is a separate repository with its own `.git` directory. Its `origin` is currently `git@github.com:adarsh-dev-hs/sell-easy.git`, on branch `main`.
- The root files (`package.json`, `scripts/`, `plan.md`, `README.md`) and `docs/` aren't tracked by either repository yet.

Run `git` commands from inside the app you changed, and open a separate PR for each repository. A change that touches both the API and the UI needs two coordinated PRs.
</Callout>

<Callout type="info" title="Env files in git">
`frontend/.gitignore` ignores `.env*` but re-includes `.env.example` (`!.env.example`), so only the example file is committed. The same applies to `backend/.env.example`; real `.env` files are never committed.
</Callout>
